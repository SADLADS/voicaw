Voicaw's bot API is Discord's API, version 10: the same REST endpoints, the same gateway and the same objects. Libraries written for Discord, like discord.js and discord.py, work with Voicaw once you point them at Voicaw's addresses. If you've written a Discord bot before, you already know most of this.

/api/v9 works too, and is the same as /api/v10.

Bots live in guilds

On Voicaw, direct messages and group chats are end-to-end encrypted: the server can't read them, so a bot can't either. Bots are only ever in guilds, which aren't encrypted. A bot can't open a DM (POST /users/@me/channels and sending a DM fail with error 50007), isn't in anyone's list of people to message, and can't be added to a group chat or called.

A bot only sees the people it shares a guild with. Fetching any other user fails with 10013 Unknown User.

No privileged intents

Intents still choose which gateway events your bot gets, but none of them needs approval: Guild Members, Guild Presences and Message Content are there for any bot that asks. A message's content is always included, in the gateway and over REST, whether or not you ask for the Message Content intent.

Commands and components

Slash commands, right-click (user and message) commands, buttons, select menus, forms, autocomplete and ephemeral replies work as on Discord. Interactions come over the gateway only. See Commands and components.

Simpler permissions

Adding a bot has one scope, bot (logging people in to your website is identify, see Login with Voicaw). Someone with Manage Guild adds your bot from its invite link. The bot then gets a role of its own holding the permissions they ticked, which can only be ones they have themselves. After that, its permissions work as anyone's: its roles, then channel overrides. See Permissions.
