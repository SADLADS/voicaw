Permissions are Discord's bitfields, as decimal strings, everywhere: roles, overwrites, the invite link's permissions. Voicaw's permissions are fewer than Discord's, so each of Voicaw's has a Discord bit, and some of Discord's come with another one.

How a bot's permissions work

As anyone's in a guild: @everyone's permissions plus those of the bot's roles (its own role and any it's given). Administrator, or owning the guild, means everything. In a channel, the overwrites apply in Discord's order: @everyone's, then the roles' (denies, then allows), then the member's own. In a thread, Send Messages in Threads stands in for Send Messages.

On top of permissions, a bot only reaches below its own highest role: it can't edit, give or delete roles at or above it, or kick, ban or change the roles of members ranked as high, and it can't give out permissions it doesn't have itself. Move its role up in the guild's settings to let it manage more.

Bits that come with another

Voicaw has no separate permission for these, so Voicaw sends them set whenever the permission they come with is. Libraries checking for them (discord.js's permissionsIn(channel).has('EmbedLinks')) get the right answer.

BitComes with
READ_MESSAGE_HISTORY (1 << 16)View Channel
EMBED_LINKS (1 << 14), ATTACH_FILES (1 << 15), USE_EXTERNAL_EMOJIS (1 << 18), USE_APPLICATION_COMMANDS (1 << 31)Send Messages
USE_VAD (1 << 25)Speak
CREATE_GUILD_EXPRESSIONS (1 << 43)Manage Emoji

When you send permissions (a role, an overwrite, an invite link), only the bits in the first table count. The ones that come with another, and Discord's bits Voicaw has no meaning for (Priority Speaker, Manage Nicknames, Moderate Members…), are ignored.

Some permissions can't be set per channel (overwritten): Kick, Ban, Administrator, Manage Channels, Manage Guild, Manage Roles, Manage Webhooks, View Audit Log, Manage Emoji, Create Invite and Mention Everyone. Those bits are dropped from an overwrite.
